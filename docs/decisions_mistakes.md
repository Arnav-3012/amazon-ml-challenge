- 2026-09-25 | Read TSVs with `quoting=csv.QUOTE_NONE` | every line has exactly 4 tab fields, but ~800 lines carry CSV-style quotes; default quoting risks merging rows. Quote chars stay as text noise for the normaliser
- 2026-09-25 | Paths resolve from the repo root via `__file__`, not cwd | `python -m src.x` runs from code/business_entity_resolution while data/output sit at the root (same layout in the zip)
- 2026-09-25 | Canonical matching space = ASCII-transliterated Latin; raw kept for the encoder | S1 is ASCII while India S2/S3 is ~25% native script (Revision 1a)
- 2026-09-25 | Normaliser precision guard = exact non-pair collision ppm from group counts, not 200k sampled random non-pairs | EDA C7 exact-name rate on random non-pairs was 0.00%; a sampled guard can't register a rule that merges businesses
- 2026-09-25 | Alias split keeps the RIGHT side as core_name | every mined `<brand> <kw> <name>` sample has the S1 name after the keyword; the left side is a generated brand
- 2026-09-25 | Legal form moved to its own `legal_form` column, not deleted | breakdown Leaf 1 trap: stripping legal suffixes merges "Acme Inc" / "Acme LLC"; eval reports core+legal collisions alongside core-only
- 2026-09-25 | Blocking score as sparse products chunked by an exact nnz bound (row cost = Σ posting lengths) | inverted-index retrieval without a custom index; memory is set by `nnz_budget`, not by data size; `--dry` gives the exact cost bound before any product (eda.py/normalise.py lesson)
- 2026-09-25 | Train blocking keeps a rank grid (m≤10, k≤60), candidates = grid cut by `finalize()` | budget curve without reruns; the cut nulls out-of-cut ranks/scores so train candidates equal a direct config run (test)
- 2026-09-25 | S1-centric top-k is per source (S2, S3 separately) | processing unit is country × source; stated in config
- 2026-09-25 | Skeleton spec amended: leading vowel → "a", non-initial y = vowel, digit tokens unchanged | spec rules as written fail its own assert istrn~eastern (istrn vs estrn); y: sistms/systems, keyr/care diverged; repeat-collapse would turn "1100" into "10"

- 2026-09-25 | Blocking A and C get adjacent-token bigrams + a rarest-2 fallback (config `bigrams`, `fallback_rarest`, default on; read only inside block.py so train = test) | 38–50% of S1 names are shared with another S1 (Revision 3), so many names are made only of common tokens; with a df cap of 1000 those names get no channel-A candidates. A bigram ("ganesh_traders") is far rarer than its parts. A record with no token under the cap keeps its 2 lowest-df linkable tokens. Fallback tokens only match records whose kept set also contains them, so their cost is bounded by fallback-row postings; `--dry` reports it, plus zero-survivor % with and without fallback
- 2026-09-25 | Product-cost bound uses the actual posting lengths (column counts of the built index), not df-table n1 | with fallback, a common token sits only in the rows that fell back, so n1 would overstate cost by orders of magnitude

- 2026-09-25 | Added combined channel X (score = A+B+C over channel-tagged tokens) | diag: per-channel ranking loses true pairs to same-score ties (38-50% S1 name collisions); widening m/k 5/30→10/60 bought +2.3pp PC for +100 cand/S1. One joint ranking lets address break name ties

- 2026-09-25 | Blocking budget chosen by perfect-matcher macro F0.5 ceiling, not PC | PC treats every pair alike; the metric is per S1 (1 of 3 missed = 0.909, singletons = 1). Ceiling picks the knee: X m5/k10, 0.9873 @ 31/S1 vs 0.9904 @ 154/S1

## Mistakes
- 2026-09-25 | Blocking v1 ranked each channel alone | per-channel top-m/k can't break ties: a name-only channel scores every same-name S1 equally, and the address evidence lives in another ranking. PC 90.3%. Should have scored the joint evidence first and kept the single channels only as recall add-ons
- 2026-09-25 | eda.py first version had unvectorized `.apply(axis=1)`/dict-loop paths over 5M+ row files, only ever smoke-tested at ~400-row scale | wasted 27+ min of the user's wall-clock time before being killed; should have sanity-checked op-count (rows x per-row cost) against real file sizes before declaring it ready, not just checked "does it run on a tiny sample"
- 2026-09-25 | First eda.py "audit every hot path" pass missed a `list(2.2M-entry dict)` rebuilt inside a 200k-iteration while loop (C7 negative sampling) — the real bottleneck, ~33 min alone | should have grepped for list()/dict() calls inside loop bodies specifically, not just `.apply(axis=1)` patterns; caught only on the SECOND killed run, wasting another ~12 min of the user's time
- 2026-09-25 | Revision 2 stated the ~1-2M brute-force ceiling applied to candidate pairs (44M), implying candidate scoring itself was infeasible brute-force | conflated the search-index cost (2.2M S1 queries × ~10M S2+S3 vectors, genuinely infeasible brute-force) with scoring already-generated candidate pairs (cheap, chunkable); the real conclusion — blocking must be ANN/inverted-index *by design*, not as a fallback — got buried under an overstated/misattributed number. See breakdown.md Revision 2a
- 2026-09-25 | Revision 2 claimed the country pre-filter gives a "~3-4x reduction for free" without deriving it from the actual class shares | should have computed `1/Σ(share²)` from the already-known US/India 60/40 train split before writing a number down; the real figure is ~1.9x on train, ~2.5x on test — meaningfully weaker than claimed, and not sufficient on its own to avoid ANN blocking. See breakdown.md Revision 2a
- 2026-09-25 | Revision 2 called the decision-layer assignment step "Hungarian" (one-to-one bipartite matching) when the EDA finding it cited (each S2/S3 -> ≤1 S1, each S1 -> many) is a many-to-one structure | Hungarian solves the wrong problem shape; the correct rule is per-record argmax-above-threshold, not a one-to-one matching algorithm. Propagated the wrong term into docs/phases.md's M2 closure entry too. See breakdown.md Revision 2a
- 2026-09-25 | normalise.py v1 used `list.eval` with non-elementwise exprs (filter/shift/cum_min), which polars runs once per row: smoke showed ~110us/row → ~560s per 5.3M-row file, ~45 min for 6 files + >1h ablation | same lesson as eda.py: cost per row was never estimated before writing. Rewritten: name kept as a string (regex for legal/honorific), drops = when→null + native `list.drop_nulls`, dedupe via one explode/group_by. Rule for this repo: inside `list.eval`, elementwise expressions only
- 2026-09-25 | REVERTED `country_marker` (strip "(india)/(france)") | ablation: +0.059pp name recall vs +0.209pp S1 name collision; "(India)" is organic in S1 (2%), stripping merges "X (India) Pvt Ltd" with "X Pvt Ltd". France's "(France)" (8% of test S1) has the same profile, so India is the proxy; revisit only with France evidence (M6)
- 2026-09-25 | REVERTED `amp_and` ("&"/"+" → "and") | ablation: turning it OFF raises name recall +0.133pp and lowers S1 collision 0.111pp; the generator drops/replaces "&" more than it spells "and", so letting punct delete "&"/"+" is better on both
- 2026-09-25 | REVERTED `landmark` (strip near/opp/behind + 1-3 tokens) | ablation: −0.021pp addr recall, +0.008pp collision; no measurable gain, and landmark tokens stay available to addr_tokens for blocking
- 2026-09-25 | `block_eval.shared_flags` rewritten from 12x eager explode+hash-join+group_by to one `list.eval` membership-test pass per channel (no explode) | the running M3b eval was taking 30+ min with no prior baseline; explode blows up row count (millions of pairs x avg tokens per list) before a join, run 3 channels x 4 (country,source) groups; `list.eval(elem.is_in(rare_frozenset))` does the same per-pair boolean directly on the list column. Verified against the old function on a hand-built + 500-row randomized case (exact `.equals()` match) before editing the eval-in-flight process's on-disk source; the running process already has the old module loaded in memory so it was not disturbed. Not yet timed on real data — confirm the speedup on the next `block_eval` run
- 2026-09-25 | Claimed per-channel ties were the main PC loss and built channel X on that | X moved PC only +0.6pp (rank-1 81.4% vs 82.2%). It was a guess from the rank-tail shape, not from miss causes; should have split misses by cause (token-level) before building. X is kept: it halves candidates at equal PC
- 2026-09-25 | Caught before shipping (strict-old-man L3 review): `base_pairs(sample)`'s first draft computed `card` (true-match count per S1) AFTER sampling, not before | card_bin feeds section 2 of blocking.md (PC by cardinality). Verified on synthetic data: sampling first made card wrong for 1,385/1,543 S1s (90%) in the test — e.g. true card 7 read as 3. Fixed: `card` now comes from `load_gt_pairs()` before any sampling; only the row selection (which pairs go into the join) samples. The row-selection-is-identical claim (same seed, same source frame) was re-verified and holds; only the aggregate-before-sampling part was missed on the first pass. Full (unsampled) runs were never affected — sample=0 takes the same path as the old code.
- 2026-09-25 | Proposed char 3-grams for the PC gap before the miss split existed | sampled eval: only 3/18,090 misses share no token; 50% share only over-cap tokens and 50% are rank cuts. Fix is name×address composite tokens in X, not char n-grams. Rule: split misses by cause before choosing a recall fix
